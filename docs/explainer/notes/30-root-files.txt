=== FILE scripts/dev-start.ps1
>>> SUMMARY
A **PowerShell script** that starts EduMate for development on Windows with one command. It opens two new windows: the backend (port 8080) and the frontend (port 5173). On the first run, and again whenever the list of frontend packages has changed (for example after a `git pull`), it also installs the frontend's packages.

Run it from the project folder:
<pre class="block">powershell -ExecutionPolicy Bypass -File scripts\dev-start.ps1</pre>
`-ExecutionPolicy Bypass` allows this one script to run even though Windows blocks scripts by default.
>>> 7
`$PSScriptRoot` is the folder holding this script (`scripts`); `Split-Path -Parent` goes one folder up, to the project root.
>>> 9-10
Prints a message, then opens a **new** PowerShell window (`Start-Process`) that goes into `backend` and runs `mvnw.cmd spring-boot:run`. `-NoExit` keeps the window open so its log stays visible.
>>> 12-13
Why the next check exists: `npm install` must run not only the first time, but also after a `git pull` that added or upgraded packages; otherwise the frontend would start with old packages and fail with "Failed to resolve import".
>>> 14
The file npm writes inside `node_modules` at the end of every install: its date is "when the packages were last installed".
>>> 15
Install if that file does not exist (never installed), **or** if `package-lock.json` (the list of exact package versions, updated by `git pull`) is newer than the last install. `-or` stops at the first true part, so the dates are only compared when the file exists.
>>> 16-20
Then go into `frontend`, run `npm install`, and come back (`Push-Location` / `Pop-Location`).
>>> 22-23
Opens a second window running `npm run dev` in `frontend` (the Vite development server).
>>> 25-27
Tells the user which address to open and the demo password.

=== FILE backend/.mvn/wrapper/maven-wrapper.properties
>>> SUMMARY
Settings for the **Maven Wrapper** (`mvnw` / `mvnw.cmd`). The wrapper lets anyone build the backend **without installing Maven**: the first time it runs, it downloads exactly the Maven version written here and keeps it in the user's home folder.

Why? Everyone who builds the project, and every build server, uses the **same** Maven version, so "it builds on my machine" problems disappear.
>>> 1
The version of the wrapper scripts themselves.
>>> 2
`only-script`: the wrapper is just the two scripts, with no extra helper `.jar` file in the repository.
>>> 3
Where to download Maven 3.9.16 from: Maven Central, the official repository.
