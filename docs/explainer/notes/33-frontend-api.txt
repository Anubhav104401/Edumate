=== FILE frontend/src/api/http.ts
>>> SUMMARY
**The one place where the frontend talks to the backend.** Every page calls a function in `endpoints.ts`, and every one of those calls `request()` in this file. Because there is only one place, every request is built and every error is handled **the same way**.

**What happens when a page asks for data, step by step.** Suppose the student presses "Pay now", and the page calls `api.fees.initiate(12)`:

1. `endpoints.ts` calls `request('POST', '/api/fees/payments', { feeDemandId: 12 })`.
2. **JavaScript object → JSON text.** `JSON.stringify({ feeDemandId: 12 })` produces the text `{"feeDemandId":12}`. JSON ("JavaScript Object Notation") is plain text that any language can read. The network can only carry text and bytes, not JavaScript objects, so the object is turned into text first.
3. **Headers** are added: labels that travel with the request.
   - `Content-Type: application/json`: "the body is JSON".
   - `Accept: application/json`: "please answer in JSON".
   - `Authorization: Bearer eyJhbGciOi…`: the login token (the "wristband"), which proves who is asking.
4. **Sending.** `fetch('/api/fees/payments', { method: 'POST', headers, body })` sends it. The address has no host or port, so it goes to the page's own origin (port 5173, or 3000 in Docker), where Vite or nginx forwards it to the backend on port 8080.
5. On the backend, Spring Security checks the token and the RoleMatrix, and **Jackson** turns the JSON text back into a Java object (`JSON → InitiatePaymentRequest(feeDemandId=12)`). The controller runs, and Jackson turns the Java answer into JSON text again.
6. **The answer comes back.** If its status is 200–299 (`response.ok`), `response.json()` turns the JSON text back into a JavaScript object for the page.
7. **Errors.** Otherwise the backend's error JSON `{"status":409,"code":"ALREADY_PAID","message":"This fee has already been paid in full."}` becomes an `ApiError`, whose `message` is already written for people, so the page can show it as it is.

The exact request as it travels:
<pre class="block">POST /api/fees/payments HTTP/1.1
Host: localhost:5173
Accept: application/json
Content-Type: application/json
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiJzdHVkZW50Ii…

{"feeDemandId":12}</pre>

**Why `fetch` and not a library like Axios?** `fetch` is built into every modern browser, so nothing needs to be installed. Axios adds conveniences (interceptors, automatic JSON), but this small file provides the same things in about 170 lines that anyone can read.

**Why is the token in `sessionStorage`?** The alternatives:
- `localStorage`: survives closing the browser. That is more convenient, but a forgotten login on a shared college computer would stay active;
- a JavaScript variable only: lost on every page refresh, which is annoying;
- an HttpOnly cookie: JavaScript cannot read it at all, which is safer against XSS, but it brings back CSRF protection and needs more server setup.

`sessionStorage` survives a refresh and disappears when the tab is closed. The token also expires after 8 hours, and React's escaping plus the CSP header protect against XSS.
