=== FILE frontend/src/pages/admissions/ApplicationsPage.tsx
>>> SUMMARY
**The admissions officer's list of applications**, with a **status filter** and a **search box** (name or application number). Data: `GET /api/admissions/applications?status=&q=`. Each row shows the applicant's avatar and name, the application number (a link), the programme, the category as a chip, the entrance and qualifying scores, a **status badge coloured by meaning** (amber while waiting for a decision, green for an offer or enrolment, red for rejected, withdrawn or reversed), and when it was submitted. An arrow at the end of the row opens the detail page.

**Why does the search wait for the button?** The filter reloads at once when changed, but the search text only takes effect when "Search" (or Enter) is pressed. Otherwise every key press would send a request to the server: typing "priya" would send five.

**DEF-036 (reflected XSS)** is prevented here as everywhere else: React writes names as **plain text**, never as HTML. An applicant who names themselves `<script>alert(1)</script>` just shows up with that odd-looking name, and nothing runs.

=== FILE frontend/src/pages/admissions/MeritListPage.tsx
>>> SUMMARY
**The merit list and seat allocation** for one programme (FR-05). Data: `GET /api/admissions/merit-list?programId=`. The officer picks a programme and presses "Generate merit list". The page shows:
- a **seat matrix**: one tile per category (OPEN, OBC, SC, ST), each with the number of seats, "11 of 11 filled" and a bar (amber while seats remain, full when filled; the tile turns green when the category is full);
- the **ranked list**: rank (the top three wear a **gold, silver and bronze medal**), application, name, category, entrance score, qualifying %, **merit score** (0.6 × entrance + 0.4 × qualifying), and the **seat** (a green OPEN, OBC… or an amber "Wait-list #3").

All the work (scoring, the deterministic tie-breaks, the two-pass seat allocation) happens in the backend's `MeritListGenerator`; this page only displays it. The list is generated fresh each time, from the applications as they are now.
