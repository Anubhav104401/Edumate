=== FILE backend/src/test/java/com/edumate/IntegrationTestBase.java
>>> SUMMARY
The parent of every **integration test**. It starts the **whole backend** in memory with the demo data loaded, and gives each test a `MockMvc`: a "fake browser" that sends HTTP requests through the real security filters, controllers, services and database, without opening a network port.

**Unit test vs integration test:**
- A *unit test* checks one class alone (for example `SgpaCalculator`). It is very fast and pinpoints the broken piece exactly.
- An *integration test* checks that the pieces work **together**: the URL, the RoleMatrix, the JSON, the transaction and the SQL. It is slower (Spring takes a few seconds to start), but it catches mistakes that unit tests cannot see.

EduMate uses both, as the report's test strategy prescribes (unit → integration → system).

All integration test classes share **one** running application and one database (Spring caches it). Each test therefore uses different demo users, so tests cannot disturb one another.
