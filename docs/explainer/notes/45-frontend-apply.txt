=== FILE frontend/src/pages/applicant/ApplyPage.tsx
>>> SUMMARY
**The applicant's whole journey on one page**, in the order an applicant needs it:

| Step | What | Backend |
|---|---|---|
| 1–3 | the form: personal details, programme and scores, guardian | `POST /api/admissions/applications` the first time, `PUT …/{id}` after that ("Save changes") |
| 4 | scanned documents: one `DocumentUpload` box per type | multipart upload with progress |
| 5 | guardian consent, **only for applicants under 18** (DPDP Rules, 2025; the fix for RR-02) | `POST /api/consent/applications/{id}/request`, then `…/verify` |
| 6 | submit (or withdraw) | `POST …/transitions {"action": "SUBMIT"}` |

**How the form becomes JSON.** The form's state is a plain JavaScript object with the same field names as the backend's `ApplicationForm` record. "Save" passes it to `api.admissions.create(form)`, and `request()` turns it into JSON text with `JSON.stringify`. Empty scores are sent as `null`, never as `""`, because the backend expects a number or nothing.

**Two layers of checks.** `validateApplication` checks the form in the browser, and the messages appear under the fields at once. If the backend still finds a problem, its `fieldErrors` (for example `{"email": "Enter a valid e-mail address."}`) are put under the same fields.

**Once submitted**, the whole page becomes read-only (inputs disabled, no upload boxes, no Save), because the backend refuses edits after submission anyway (NOT_DRAFT).

**Every text** here is under `apply` in `messages.ts`, and the document labels are under `documentTypes`.
