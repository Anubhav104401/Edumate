=== FILE frontend/src/components/DocumentUpload.tsx
>>> SUMMARY
**One box on the "Documents" step of the application form**, one box per document type. It shows whether the document is uploaded, lets the applicant **drag a file onto it** or **click to choose one**, checks the file in the browser, uploads it with a **progress bar**, and offers **View** and **Remove**.

**The whole journey of one file:**

<pre class="block">1. Applicant drops "aadhaar.pdf" on the "Identity proof" box   (or clicks and picks it)
2. checkFile() in the browser:  empty?  bigger than 5 MB?  wrong extension?  real first bytes?
      └─ problem → red toast, nothing is sent
3. FormData { type: "ID_PROOF", file: &lt;the bytes&gt; }
4. XMLHttpRequest POST /api/admissions/applications/7/documents   (Authorization: Bearer …)
      └─ progress events → "Uploading… 35%" and a growing bar
5. Vite (5173) or nginx (3000) forwards it to Spring Boot (8080)
6. Tomcat reads the multipart body (5 MB limit) → DocumentController → DocumentService:
      owner? draft? empty? ≤ 5 MB? real kind by magic bytes? allowed for ID_PROOF?
      SHA-256 → store under applications/7/&lt;random&gt;.pdf → save the index card → audit
7. 200 OK with the document's JSON  → green toast "Identity proof (Aadhaar card or passport) uploaded."
8. onChanged() → the page reloads the list → the box shows name, size, time and fingerprint</pre>

**Why check in the browser if the server checks anyway?** Speed and kindness. A wrong 4 MB file is refused in a split second, before a slow upload over a weak connection. The browser checks are only a **convenience**. Someone could skip them (for example with `curl`), so the server repeats **every** check and is the one that really decides.

**Accessibility.** The drop area is also a **button**: it can be reached with the Tab key and activated with Enter or Space. People who cannot use a mouse can still upload.

=== FILE frontend/src/utils/fileChecks.ts
>>> SUMMARY
Checks a file **in the browser, before uploading**, in this order:

| # | Check | Message (from `messages.ts`, `t.upload`) |
|---|---|---|
| 1 | empty (0 bytes) | "“marks.pdf” is empty." |
| 2 | larger than 5 MB | "“marks.pdf” is larger than 5 MB. Please scan it at a lower resolution." |
| 3 | extension not allowed | "“marks.docx” is not an accepted file. Use PDF, JPEG or PNG." |
| 4 | first bytes are not really that kind | "“marks.pdf” does not look like a real PDF, JPEG or PNG file." |

Check 4 reads **only the first 8 bytes** of the file (`file.slice(0, 8)`), not the whole file, so it is instant even for a 5 MB scan. It uses the same magic numbers as the backend's `FileTypeSniffer`.

**These lists must match the backend's `DocumentType.java`.** If they differed, the browser might refuse a file the server would accept (annoying), or allow one the server refuses (the server's message is then shown, so nothing unsafe happens).
>>> 12
The three file kinds, as a TypeScript type: a value can only be one of these three texts.
>>> 15-20
The kinds each document accepts. The photo cannot be a PDF.
>>> 23
The required documents: photo, ID proof, Class 12 marks card.
>>> 25-28
The file-name endings of each kind. JPEG files may end in `.jpg` or `.jpeg`.
>>> 33
`acceptAttribute`: for `['PDF','JPEG']`, gives `.pdf,.jpg,.jpeg`. `flatMap` turns each kind into its list of endings and joins the lists into one.
>>> 38
`describeKinds`: for `['PDF','JPEG','PNG']`, gives "PDF, JPEG or PNG" (all but the last joined with commas, then "or" and the last).
>>> 43
`starts(sig)`: true if every byte of the signature equals the file's byte at the same position.
>>> 44-46
PDF (`%PDF-`), PNG (`\x89PNG\r\n\x1a\n`) or JPEG (`FF D8 FF`).
>>> 47
None matched.
>>> 55-56
Check 1: empty file.
>>> 58-59
Check 2: over 5 MB (`MAX_UPLOAD_BYTES` in `config.ts`).
>>> 61-64
Check 3: does the lower-cased name end with one of the allowed endings? `MARKS.PDF` counts as `.pdf`.
>>> 66
Check 4: reads the first 8 bytes. `file.slice(0, 8)` takes just that piece, and `arrayBuffer()` reads it (which takes a moment, hence `await`).
>>> 67-69
Recognise the kind; if it is unknown, or not one this document accepts, refuse.
>>> 71
`null` = no problem, go ahead and upload.
