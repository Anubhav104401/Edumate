=== FILE frontend/src/components/Toast.tsx
>>> SUMMARY
**Toasts** are the small messages that pop up in the bottom-right corner and vanish after 5 seconds: "Approval recorded.", "Book returned. Fine charged: ₹12.00.", "That code is not correct. Attempts left: 3." (They are named after toast popping out of a toaster.)

Any page shows one with:
<pre class="block">const toast = useToast();
toast.success(t.apply.savedToast);    // green
toast.error(errorMessage(err));       // red</pre>

**To change how long they stay**, edit `TOAST_DURATION_MS` in `config.ts`. **To change their colours**, edit the `--good`, `--bad`, `--info` and `--warn` colours in `theme.css`.

**Accessibility:** the stack of toasts is marked `role="status"` and `aria-live="polite"`, so screen readers read each new message aloud without interrupting what they are currently reading (WCAG 2.1, which the report's usability objective refers to).

**Why toasts instead of `alert()`?** The browser's `alert()` freezes the whole page until OK is clicked, looks different in every browser, and cannot be styled. Toasts do not block work, and several can stack up.

=== FILE frontend/src/components/ConfirmDialog.tsx
>>> SUMMARY
**"Are you sure?" dialogs**, for actions that cannot easily be undone: publishing results, reversing an enrolment, removing a document.

A page asks like this, and **waits** for the answer:
<pre class="block">const confirm = useConfirm();
if (await confirm(t.resultsManage.confirmPublish)) {
  // the user clicked "Confirm"
}</pre>

**How the waiting works.** `confirm(...)` returns a *Promise*: a promise of an answer that will come later. It stores the promise's `resolve` function and shows the dialog. When a button is clicked, `resolve(true)` or `resolve(false)` is called, which fulfils the promise, and the page's `await` continues with that answer.

**Why not the browser's `window.confirm()`?** It freezes the page, cannot be styled or translated, and looks different in every browser. This dialog uses EduMate's own look and `messages.ts` texts. Clicking outside it counts as **Cancel**, and **Confirm** has the keyboard focus, so Enter confirms.

The type of the `confirm` function: a message and an optional button label in, a promise of true/false out.
>>> 14-17
The question currently on screen: its message, the confirm button's label, and the `resolve` function that will deliver the answer.
>>> 20
The context.
>>> 25-28
`confirm(message, label)`: creates a Promise and stores its `resolve` together with the message, which makes the dialog appear. The button label defaults to "Confirm".
>>> 31-33
`answer(value)`: delivers the answer to the waiting page and hides the dialog.

=== FILE frontend/src/components/ErrorBoundary.tsx
>>> SUMMARY
A **safety net around every page**. If a page crashes while drawing itself (for example the server sent data in an unexpected shape), React normally removes **everything** from the screen, leaving a blank white page. This component catches the crash and shows a friendly red message instead: "This page could not be displayed. Something unexpected happened while drawing it. Choose another page from the menu, or reload the browser tab." The top bar and menu keep working.

**Where it came from.** While EduMate was being built, the Role matrix page crashed because Spring 7 sent HTTP methods as `{}` (see `AdminController`), and the whole app went blank. The backend was fixed, and this boundary was added so any **future** bug stays contained to one page.

`Layout.tsx` wraps the current page in `<ErrorBoundary resetKey={location.pathname}>`. When the person goes to another page, the address changes, and the error is forgotten.

**Why a class?** React lets only *class components* catch errors (`getDerivedStateFromError`); there is no hook for it yet. That is why this file looks different from the others.
