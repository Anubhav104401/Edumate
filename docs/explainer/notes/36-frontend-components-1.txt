=== FILE frontend/src/components/Toast.tsx
>>> SUMMARY
**Toasts**: the small messages that slide up in the bottom-right corner and disappear after a few seconds ("Attendance saved.", "Something went wrong."). Any page shows one with:
<pre class="block">const toast = useToast();
toast.success(t.takeAttendance.savedToast);</pre>

Since release 3.0 the drawing is done by the **Sonner** library: messages stack neatly, can be swiped away, pause while the mouse is over them, and are announced to screen readers. This file keeps EduMate's own small API (`success`, `error`, `info`, `warning`) in front of Sonner, so **no page had to change**, and swapping Sonner for something else later would touch only this file. That is the *adapter* idea: wrap an outside library behind your own interface.

=== FILE frontend/src/components/ConfirmDialog.tsx
>>> SUMMARY
**"Are you sure?" dialogs.** A page asks, and **waits** for the answer:
<pre class="block">const confirm = useConfirm();
if (await confirm(t.resultsManage.confirmPublish)) { …publish… }
if (await confirm(t.apply.confirmWithdraw, t.apply.withdraw, 'danger')) { … }   // red button</pre>

`confirm(...)` returns a **Promise**, a value that arrives later. `await` pauses the page's function (not the whole page) until the person clicks Confirm (`true`) or Cancel / presses Escape (`false`).

**Accessibility, done by Radix UI's AlertDialog.** A proper dialog must: trap the keyboard inside it (Tab cannot wander to the page behind), close on Escape, tell screen readers "this is an alert dialog" with its title and description, hide the page behind from them, and return the focus to the button that opened it. Radix does all of that; `motion` adds the entrance and exit animation. For a **dangerous** action (reject, withdraw, remove) the button is red, the icon is a warning triangle, and the keyboard focus starts on *Cancel*, so an absent-minded Enter does not destroy anything.

=== FILE frontend/src/components/ErrorBoundary.tsx
>>> SUMMARY
**A safety net around every page.** If a page crashes while drawing itself, React would normally remove the whole app from the screen. This component catches the crash and shows a friendly message instead, with a "Reload the page" button, while the menu stays usable so the person can go to another page.

React only supports this with a **class component** (the older way of writing components), which is why this file looks different from the others.
>>> 11-14
Its inputs: the page to protect, and `resetKey`, the current address. When the address changes, the error is forgotten, so moving to another page recovers.
>>> 17-18
Its memory: has the page crashed?
>>> 21
`ErrorBoundary extends Component<Props, State>`: a class component with those inputs and that memory.
>>> 22
At first, nothing has crashed.
>>> 24-25
React calls this when anything inside crashes while drawing: set `failed` to true.
>>> 28-29
Also called on a crash: write the details to the browser's console for developers.
>>> 32-34
After every update: if the address changed and the page had crashed, try again.
>>> 38-41
Drawing: if it crashed, show a card with the "empty state" layout…
>>> 42-43
…a floating bug icon in red…
>>> 47-48
…and a button that reloads the browser tab.
>>> 53
Otherwise draw the page normally.

=== FILE frontend/src/components/Layout.tsx
>>> SUMMARY
**The frame around every page after login**: the side menu on the left, the top bar, and the current page in the middle. It also owns the things that belong to the whole frame rather than to one page:
- the **command menu**, opened with Ctrl+K (⌘K on a Mac) from anywhere;
- the **phone drawer**: on narrow screens the side menu slides in over the page, with a dimmed backdrop;
- the **collapsed menu** (icons only), remembered in the browser;
- the **reading-progress line** along the top and the **back-to-top** button;
- a **"Skip to content"** link for keyboard users.

The page itself is drawn by `<AnimatedOutlet />` (see `motion/PageTransition.tsx`), which animates each change of page.
