=== FILE frontend/src/pages/admissions/ApplicationDetailPage.tsx
>>> SUMMARY
**One application as the admissions officer (or admin) sees it**, at `/admissions/<id>`:
- three cards: personal details (with a "Minor (17)" badge when relevant), programme and scores, and guardian with consent status;
- **all five document boxes**, read-only. Staff can press **View** to open a scan. Each view is written to the audit log as DOCUMENT_VIEWED, because these can be a minor's personal documents;
- the **consent history** (requested / granted / revoked, with the masked guardian contact);
- the **decision** card: a reason box and **one button per action the state machine allows for this role** (for example Shortlist and Reject on an UNDER_REVIEW application). Reject and Reverse enrolment are red.

The buttons come from the backend's `allowedActions`, built from the same table that enforces the rules, so the page can never offer a button the backend would refuse (except when the rules need a reason and none was typed: then the backend answers "Please give a reason for this decision.").
