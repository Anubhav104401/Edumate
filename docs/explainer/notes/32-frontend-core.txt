=== FILE frontend/src/main.tsx
>>> SUMMARY
The **very first frontend code that runs**. The browser loads `index.html`, which loads this file. It loads the fonts and the stylesheets, then tells React to draw `<App />` inside `<div id="root">`.

**The order of the stylesheet imports matters.** Later styles win when two rules are equally specific, so the order is: fonts → Lenis's small helper styles → `theme.css` (the design tokens) → `app.css` (how everything looks) → `landing.css` (the public pages).
>>> 18
`document.getElementById('root')` finds the empty div in `index.html`. The `!` tells TypeScript "I am sure this is not null" (the div is always there). `createRoot(...)` makes that div React's drawing area, and `.render(...)` draws what follows into it.
>>> 19
`<StrictMode>`: a development-only helper. It deliberately runs some code twice to reveal hidden mistakes (for example effects that forget to clean up). It has no effect in the production build.
>>> 20
The whole application.

=== FILE frontend/src/App.tsx
>>> SUMMARY
The **map of the whole frontend**: which address shows which page, and which roles may open it.

**Routing** means choosing what to show based on the address in the browser's address bar. React Router watches the address. When it changes (a menu link is clicked, or the user presses Back), it shows the matching page **without asking the server for a new HTML page**.

**The layers, from outside to inside** (each "provider" makes something available to every component inside it, without passing it through each level by hand; this is React's *context* feature):
1. `BrowserRouter`: routing, using the real address bar;
2. `ThemeProvider`: light / dark / "same as my computer", and the theme switch;
3. `MotionConfig`: one setting for every animation: honour the computer's "reduce motion" option;
4. `SmoothScroll`: Lenis smooth scrolling for the whole page;
5. `ToastProvider`: any page can pop up a short message;
6. `ConfirmProvider`: any page can ask "Are you sure?";
7. `AuthProvider`: who is logged in, and the login/logout functions;
8. `Routes`: the address → page table.

The order is not arbitrary: an inner layer may use an outer one. The toasts need the theme (to be light or dark), the confirm dialog needs smooth scrolling (to pause it while open), and the login state needs toasts (to say "Your session has ended").

**Code splitting.** Before release 3.0 all pages were in one big JavaScript file, downloaded in full on the first visit. Now every page is loaded **lazily**: its code is a separate small file, fetched the first time that page is opened. `npm run build` prints one file per page (`MyFeesPage-….js`, 5 kB). The login page stays in the main file, because almost every visit starts there.

**Two guards:**
- every page except `/login` and `/welcome` is inside `<RequireAuth>`: not logged in → sent to the login page (or, for the bare address `/`, to the welcome page);
- `only([...roles], page)` additionally checks the role: logged in but the wrong role → a "not allowed" message.

**Important:** these guards only decide what the **screen** shows. The real protection is the backend's RoleMatrix, which checks every request. Someone who changes the frontend's code in their own browser still gets 403 from the server.

**To add a page:** create the page file, add a `lazyPage(...)` line and a `<Route>` here, and add a menu line (with an icon) in `navigation.ts`.
>>> 24-25
`lazyPage(load, name)`: a small helper around React's `lazy()`. `lazy` expects a file whose **default** export is the component, but EduMate's pages use **named** exports (`export function MyFeesPage`). So the helper waits for the file (`load()`), then hands `lazy` an object whose `default` is the named component. `K extends string` lets TypeScript check that the name really exists in that file.
>>> 28-52

The public welcome page is lazy too, because it holds the biggest animations and a signed-in user never needs it.

=== FILE frontend/src/config.ts
>>> SUMMARY
Frontend **settings that are neither text nor colours**. (Text lives in `i18n/messages.ts`, colours in `styles/theme.css`.)

Some values here must **match the backend**. They are repeated so the browser can warn **before** sending anything (for example "this file is larger than 5 MB") instead of after a slow upload. If you change one side, change the other too. Even if they disagree, the backend's value always wins, because the server checks again.

Release 3.0 added the settings of the new interface at the end: how smooth the scrolling is, where the browser remembers the theme and the collapsed menu, the command-menu key, and when each lecture period starts.
>>> 7
`API_BASE = ''`: every backend address starts from the page's own origin, so requests go to `/api/...` on the same host and port. In development Vite forwards them to port 8080; in Docker nginx does. The frontend code is the same in both cases.
>>> 10
The attendance threshold shown on screen (75%). It must match the backend's `edumate.academic.attendance-threshold-percent`.
>>> 13
The largest upload: 5 × 1024 × 1024 = 5,242,880 bytes. It must match `spring.servlet.multipart.max-file-size: 5MB`.
>>> 16
The demo password shown on the login page.
>>> 19-36
The demo usernames listed on the login page, in display order. `as const` makes TypeScript treat the list as fixed, so `messages.ts` can be checked to have a description for each one.
>>> 39
`DEMO_ROLES`: the role of every demo account, so the login page can show the matching icon (a graduation cap for students, a shield for administrators…). `(typeof DEMO_USERNAMES)[number]` means "any one of the usernames above", so TypeScript insists that **every** demo account has a role here and that no unknown name sneaks in.
>>> 40-55
One line per demo account. Names containing a dot (`'kavya.rao'`) need quotes, because a dot is not allowed in a bare JavaScript key.
>>> 59
Show the demo helper only in development. `import.meta.env.DEV` is `true` under `npm run dev` and `false` in `npm run build`, so a production build never advertises the demo accounts.
>>> 62
How long a toast stays on screen: 5,000 ms = 5 seconds.
>>> 65-66
The timetable grid's days (1–5 = Monday–Friday) and periods (1–6), the same as the backend's `TimetableSolver.DAYS` and `PERIODS`.
>>> 69
Smooth scrolling strength. Each animation frame, Lenis moves the page 10% (0.1) of the remaining distance to where the wheel asked it to go, which gives a soft glide that slows down as it arrives. `1` would turn the smoothing off.
>>> 72
The `localStorage` key for the theme choice. `public/theme-init.js` reads the same key before the page is drawn, so the two must stay identical.
>>> 75
The `localStorage` key for "the side menu is collapsed".
>>> 78

>>> 81

>>> 84
When each period starts, counted in **minutes after midnight**: 9 × 60 = 540 is 9:00, 14 × 60 = 840 is 2:00 pm. Index 0 is unused so that `PERIOD_STARTS[1]` is period 1. The timetable uses this to highlight the lecture running right now.

=== FILE frontend/src/navigation.ts
>>> SUMMARY
The **side menu** for each role: which links appear, in which order, under which small heading, and with which **icon**. The link texts come from `messages.ts` (`t.nav.…`), so renaming a menu item means changing only that text.

This one list feeds five places, so they can never disagree: the side menu, the command menu (Ctrl+K), the breadcrumb in the top bar, the icon and heading above each page title, and the "Jump back in" shortcuts on the dashboard.

A menu link without a matching route in `App.tsx` would lead to "page not found", and a route without a menu link is reachable only by typing its address. So always add both.

Students and guardians share one menu (a guardian sees their child's pages).
