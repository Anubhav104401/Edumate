=== FILE frontend/src/pages/exam/ResultsManagePage.tsx
>>> SUMMARY
**The examination superintendent's results workflow**, where the **Safety** objective (two-person approval) and **TC-015 / DEF-027** (publish exactly once) can be seen:

<pre class="block">Compute ──► Approve (person 1) ──► Approve (person 2, must be different) ──► Publish</pre>

- **Compute** (top card): choose exam session, programme and semester. If marks are missing, the backend refuses with "1 mark entries are still empty…". Otherwise it shows a toast such as "Computed 60 results: 57 passed, average SGPA 7.68."
- **Result sets**: one **card per set**, with the programme and semester, the session code, a status badge, and a **step tracker** (Computed → 1st approval → 2nd approval → Published) that makes it obvious at a glance how far along each set is. Under it: who approved it, who published it and when, and only the **right** button for its status: Approve for COMPUTED / AWAITING_SECOND_APPROVAL, Publish for APPROVED.
- If the **same** person approves twice, the backend refuses: "You gave the first approval. A second, different exam superintendent must approve."
- **Publish** asks for confirmation first, because publishing is final.
- "Consolidated marks" shows the cohort's marks sheet under the list.

The page **only shows buttons**; every rule is enforced by the backend. Even if two superintendents click Publish at the same moment, only one succeeds (the atomic UPDATE).

=== FILE frontend/src/pages/exam/ConsolidatedReportView.tsx
>>> SUMMARY
**The consolidated marks table** of one result set: one row per student, one column per course with the student's **coloured grade chip**, then SGPA, CGPA and PASS/FAIL, with a **"Download CSV"** button for spreadsheets.

This is exactly the report of **TC-017 / DEF-031**: it contains **every** student's marks, so only examination superintendents and administrators may load it. When a student tries, the backend answers 403 and records the attempt in the audit log. This component is used by both the results workflow page and the reports page.

**CSV safety.** The CSV comes from the backend, which puts a `'` in front of any cell starting with `=`, `+`, `-` or `@`. Spreadsheet programs would otherwise run such cells as formulas (*CSV formula injection*).
>>> 19-21
`downloadCsv`: saves the report as a file. It first fetches the CSV **with the login token**, as a `Blob` (a lump of bytes in the browser's memory). A plain link could not send the token.
>>> 22
A temporary local address for those bytes (`blob:http://…`).
>>> 23-26
The download trick: create an invisible link to that address, with the `download` attribute naming the file ("consolidated-marks-7.csv"), and click it from code. The browser then saves the file instead of opening it.
>>> 27
