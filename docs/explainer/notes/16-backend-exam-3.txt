=== FILE backend/src/main/java/com/edumate/exam/ResultPublicationService.java
>>> SUMMARY
The **two-person gate** in front of result publication, and the publication itself.

- **approve** (called twice): the first approval moves COMPUTED → AWAITING_SECOND_APPROVAL. The second moves AWAITING_SECOND_APPROVAL → APPROVED, but only if it comes from a **different** superintendent. If the same person clicks Approve twice, they get "You gave the first approval. A second, different exam superintendent must approve."
- **publish**: APPROVED → PUBLISHED, done with the one-statement atomic update in `ResultSetRepository` (fix for DEF-027). After a successful publish, one e-mail per student is **queued** in the outbox (sent later by the dispatcher), the cache of published results is cleared, and an audit line is written.

Why two people? The SQA Plan's Safety objective: wrong results reach thousands of students instantly and cannot be "un-seen". Requiring two independent people to look at the numbers makes a single person's mistake (or misuse) much less likely to reach students. Banks use the same "four-eyes principle" for large payments.

=== FILE backend/src/main/java/com/edumate/exam/ResultQueryService.java
>>> SUMMARY
Reads **one student's published results** for the "My results" page, with the course-wise grades of each semester.

Two important points:
- **Only PUBLISHED sets** are read. Whatever a student does, they cannot see results that are still being computed or approved.
- **Caching.** On results morning thousands of students open this page within minutes, often pressing refresh repeatedly. The report's performance objective (NFR-01) is a response under 2 seconds at 3,000 users. `@Cacheable` remembers each student's answer the first time it is worked out; later requests get the remembered answer without touching the database. In development the cache is an in-memory map; in Docker it is **Redis**, a fast memory store shared by all backend copies. The cache is cleared whenever results are published.

The answer is built with three queries whatever the number of semesters: the published rows, then all their course grades, then all the courses involved.

>>> SUMMARY
Lets a teacher see and **amend internal-assessment marks** of their own course (FR-17; the RTM names MarksEntryService and AuditLogger for this requirement).

Every amendment:
1. must come from the course's own teacher (`CourseAccess.requireTaughtBy`);
2. must be based on the latest version of the mark (otherwise 409 STALE_UPDATE);
3. is refused once the cohort's results are approved or published (409 RESULTS_LOCKED);
4. must carry a **reason** (the frontend asks for one; the request rules require it);
5. writes an audit line with the **old value and the new value**, who, when and why.

Point 5 is the fix for design defect **DR-04** / test defect **DEF-022** ("audit record stores the new mark only; the prior value is lost, defeating dispute resolution"). Test case **TC-012** in the report: "Amend an internal assessment mark from 18 to 22: change applied and audit record written with prior value, new value, actor and timestamp". In the demo data, student 23BTRCS003 has 18 in DBMS so this can be shown live.

If the cohort's results were already **computed** (but not yet approved), changing a mark sends the result set back to DRAFT, because the computed SGPAs are now out of date.

=== FILE backend/src/main/java/com/edumate/exam/ReportService.java
>>> SUMMARY
The two **cohort-wide reports**:
- **Consolidated marks** of a result set: every student's grade in every course, SGPA, CGPA, credits and outcome, as JSON for the screen or as a **CSV** file for Excel.
- **Attendance shortfall**: every course of a programme-semester with the students of a section below the minimum.

Both contain every student's data, so the RoleMatrix restricts them to EXAM_SUPERINTENDENT and ADMIN. This is the fix for test defect **DEF-031** (test case TC-017): in the old system any logged-in student could download the consolidated marks of the entire cohort. The report also checks the campus: a superintendent cannot read another campus's report.

**CSV safety.** A CSV cell that starts with `=`, `+`, `-` or `@` is treated by Excel as a **formula**. A malicious name such as `=HYPERLINK("http://evil…")` could run when the file is opened. This is called CSV (or formula) injection. The `cell` method puts an apostrophe in front of such values so Excel shows them as plain text, and wraps every cell in quotes (doubling any quote inside) so commas in names do not break the columns.
