>>> SUMMARY
**The administrator's timetable planner** (FR-14), where **TC-011** can be shown live:

<pre class="block">Generate new draft ──► (optionally) Move lectures ──► see clashes ──► Publish draft</pre>

1. Choose programme, semester and section, and press **Generate new draft**. The backend's solver (backtracking with "most constrained first") fills the week without clashes, working around lectures the same teachers already give in other sections.
2. A **Draft / Published** switch (a `Segmented` control whose highlight slides between the two) shows either version, with the number of lectures in each. Students keep seeing the published one until the draft is published.
3. Each draft lecture has a **Move** button, which opens a dialog (day, period, room). The dialog is a **Radix UI Dialog**: it traps the keyboard focus inside itself, closes on Escape or a click outside, and tells screen readers it is a dialog; motion makes it spring in and out, and the page behind it stops scrolling while it is open.
4. Moving a lecture onto a slot where its teacher, section or room is already busy **does not fail**. Instead the grid outlines the clashing lectures in red, and a red box lists each clash ("Teacher double-booked: Monday P2").
5. **Publish draft** is refused by the backend while any clash exists: "1 clash(es) must be fixed before this timetable can be published." This is TC-011's expected result.
6. At the bottom, the **workload** table shows each teacher's hours per week (with a bar measured against 20 hours) and the course codes they teach.
