=== FILE frontend/src/pages/student/MyAttendancePage.tsx
>>> SUMMARY
**"My attendance"** for a student, or **"Your child's attendance"** for a guardian (the same page; the backend works out whose attendance to send from the login token). Data: `GET /api/attendance/me`.

The page, from top to bottom:
1. A red warning box if the student is below the minimum in any course (and has no medical exemption there).
2. **A summary strip**: a ring with the overall percentage across all courses, the number of courses and of classes held, and three badges counting the courses that are "On track", "Careful" and "Below minimum".
3. **One card per course**: a progress ring (green / amber / red by status) that draws itself, the course code and name, "18 of 24 · 75.00%", a status badge, and **how many more classes the student can still miss** and stay at or above 75 % ("Can still miss: 2 classes", or "Cannot reach the minimum any more").

The three statuses are decided by the backend (`AttendanceSummaryService.java`): **SHORTFALL** below the minimum, **WARNING** when at most two more classes can be missed, **OK** otherwise. The page only colours them.

**Exactly 75 % is enough** (the subtitle says so). This was defect DEF-019 of the SQA report (review finding RR-04, test case TC-009): the old system used `>` instead of `≥`, and a student at exactly 75.00 % was wrongly blocked.

=== FILE frontend/src/pages/student/HallTicketPage.tsx
>>> SUMMARY
**The hall ticket page**: is the student allowed to sit the coming exams, course by course, and **why**? Data: `GET /api/exams/hall-ticket/me`.

It is drawn like a **real admit card**: a "ticket" with the candidate's name, USN, exam session and start date on the left, and a tear-off **stub** on the right, separated by a dashed line with two half-circle notches (CSS in `app.css`). On the stub, an **"Eligible"** (green) or **"Not yet"** (amber) stamp, in capitals, **thumps down**: it starts at 2.2 × its size, transparent, and lands with a springy bounce (`@keyframes stamp`).

Below it, one row per course: a tick or cross, the attendance (a green or red badge), whether internal assessment is complete, whether a medical exemption applies, the **decision-table rule** that decided it (R1–R5), and the reasons.

Showing the rule and reasons, rather than only "not eligible", means a student knows exactly what to fix, and staff can check every decision against the regulation (the report's decision-table test cases TC-008 to TC-010).

**Printing.** The "Print" button calls the browser's own print dialog (`window.print()`). A `@media print` block in `app.css` hides the sidebar, top bar, toasts and anything marked `no-print`, removes shadows, and keeps each card on one sheet, so only the ticket is printed.

=== FILE frontend/src/pages/student/MyResultsPage.tsx
>>> SUMMARY
**"My results"**: every **published** semester. Data: `GET /api/exams/results/me`.

The page, from top to bottom:
1. **A trend chart** of SGPA (grade point average of one semester) and CGPA (cumulative: all semesters so far) per semester. Its lines draw themselves like a pen when scrolled to; hovering or using the arrow keys shows a read-out for one semester (`TrendChart` in `components/charts.tsx`).
2. Beside it, **the current CGPA** as the page's one big number, counting up, with the latest SGPA, PASS/FAIL and a bar of credits earned out of registered.
3. **One card per semester, newest first**: SGPA, CGPA, PASS/FAIL, credits, when it was published, and a table of courses with marks, a **coloured grade chip** (S and A green, B and C blue, D and E amber, F red) and grade points.

The tables repeat every number the chart shows, in plain text, so nothing depends on being able to see the chart (a screen-reader user, or someone who prints the page, loses nothing).

Only **published** results ever reach this page; the backend's query filters on PUBLISHED. On results morning thousands of students open this page at once, so the backend serves it from the **cache** (`@Cacheable("publishedResults")`, Redis in Docker) instead of asking the database each time.

>>> SUMMARY
**"My fees"**, for a student (or "Your child's fees", for a guardian). Data: `GET /api/fees/me`. It shows:
1. **a summary strip**: the **amount outstanding** (with an amber wallet if something is due, green if nothing is), "₹62,500 paid of ₹1,25,000 billed", and a ring showing the share paid;
2. the **fee demands** (bills), each with its amount, paid, due, due date, a status badge (Paid / Due / Overdue) and a **"Pay now"** button;

**What "Pay now" does:**
