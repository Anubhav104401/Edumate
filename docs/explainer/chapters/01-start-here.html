Start here: what this guide is and how to read it

This guide explains EduMate, the education-automation software built from the SQA activity report "Automation Software for an Educational Organization" (course 23CSE701, Anubhav Kumar, 23BTRCT015). The report calls the system EduAutomate; the code calls it EduMate. They are the same thing.

It assumes you know nothing about programming. Every idea is explained the first time it appears, usually with an everyday comparison in a yellow box like this one:

Like a school A big school has a gate with a guard, an office with files, teachers, a notice board, and a rule book. EduMate is the same, but made of programs: a guard (security), files (the database), workers (services), a notice board (the screens) and a rule book (the RoleMatrix and the settings).

What EduMate does

It runs the everyday paperwork of a university with several campuses:

AreaWhat people do in EduMateWho
AdmissionsApply online, upload scanned documents, get guardian consent for minors, be reviewed, shortlisted, offered a seat, enrolled; merit list with reserved seatsApplicant, admissions officer
AttendanceTeachers take attendance per lecture; students and parents see their percentagesFaculty, student, guardian
ExaminationsMarks entry with an audit trail, hall-ticket eligibility, SGPA/CGPA computation, two-person approval, publication, reportsFaculty, exam superintendent, student
FeesBills, online payment through a (simulated) bank gateway, receipts, account statementsStudent, guardian, accounts officer
TimetableAutomatic clash-free timetable, manual adjustment, clash detection, publication, workloadAdministrator, faculty, student
LibraryCatalogue search, issue and return, finesLibrarian, student
AdministrationAudit log, message outbox, role matrix, dashboards for every roleAdministrator

The two halves of this guide

  1. The chapters (this part) tell the story: computers from zero, the technologies, how the pieces talk to each other, how a request travels, security, the document upload system, the algorithms, why each choice was made, how the interface looks and moves, how to change things, how it is tested, how to run it, and questions an examiner may ask.
  2. Every file, every line (the last part) goes through every file of the project. Open a file by clicking its name. Each row shows the line number, the line, and what it means. White explanations were written by hand; grey ones were produced automatically for repetitive lines (imports, closing brackets, comments, settings).

Useful controls on this page

  • The search box at the top filters the file list by file name or title: type Payment or messages to see only those files. To find a word anywhere on the page (for example bcrypt), use your browser's own Find: Ctrl+F (Cmd+F on a Mac). Open all files first if the word may be inside one.
  • Open all / Close all in the file section opens every file at once (the page becomes very long).
  • The theme button switches between light and dark.
  • Blue links such as messages.ts jump to that file; links ending in a line number jump to that exact line.
