Cookbook: how to change any text, colour, message, alert or limit

EduMate was built so that the things people most often want to change each live in one known place. This chapter is a set of recipes. After a change:

  • frontend files (frontend/…): the browser updates by itself within a second while npm run dev runs;
  • backend files (backend/…): stop the backend (Ctrl+C) and start it again (mvnw spring-boot:run);
  • then run the tests (chapter 12), because some tests check exact messages.

Recipe 1: change any text on the screen

Every word the frontend shows is in frontend/src/i18n/messages.ts, in one object called t, grouped by screen:

login: {
  title: 'Sign in to EduMate',
  submit: 'Sign in',                      ← change the words between the quotes
  …
},

Pages never contain the words themselves; they write {t.login.submit}. So changing 'Sign in' to 'Log in' changes the button everywhere it appears.

Texts with blanks in them

issuedToast: (title: string, due: string) => `“${title}” issued. Due back on ${due}.`,

This is a small function: the page fills in title and due. You may reword everything outside the ${…} parts, and move those parts around, but keep their names. The text is written between back-ticks (`).

Rules for editing safely

  • Change only the text between the quotes. Keep the key on the left (submit:) and the comma at the end.
  • If your text contains an apostrophe, use double quotes around it: guardianTitle: "Your child's fees",.
  • The satisfies Record<…> lines make TypeScript check that every status, role and document type has a text. If you delete one, npm run build tells you.
  • To translate the whole app (for example to Hindi or Kannada), translate the values in this one file.

Recipe 2: change an error message that comes from the backend

Business-rule messages ("This fee has already been paid in full.") are written in Java, next to the rule that produces them, and the frontend shows them exactly as sent. To reword one, find it in the table below, open the file at the given line, and edit the text in quotes. Do not change the code (the "ALREADY_PAID" part): tests and screens use it.

{{BACKEND_MESSAGES}}

Form-field messages

Messages under individual form fields come from the rules on the request records, for example ApplicationForm.java:

@NotBlank(message = "Enter your full name.") @Size(max = 120) String fullName,

The browser shows its own copy of these first (t.apply.validation in messages.ts); change both if you want the same words either way.

General messages

The messages for malformed JSON, bad parameters, too-large files, conflicting edits, "permission denied" and unexpected errors are in GlobalExceptionHandler.java. Login messages are in LoginAttemptService.java. The general frontend messages (server unreachable, session ended, page crashed) are under errors in messages.ts.

Recipe 3: change a colour, font, size or animation speed

Every colour, font, size, corner, shadow and animation curve is a design token: a CSS variable in frontend/src/styles/theme.css. Every component uses the tokens, never raw values, so changing one line changes the whole app, in both themes.

How a colour is written. Each colour holds its light-mode and its dark-mode value together:

--color-primary: light-dark(oklch(0.52 0.2 264), oklch(0.74 0.14 262));
                            └─ light mode ───┘  └─ dark mode ────┘

oklch(L C H) describes a colour the way people see it: Lightness from 0 (black) to 1 (white), Chroma (how colourful) from 0 (grey) to about 0.37, and Hue as an angle on the colour wheel: 25 red, 65 amber, 155 green, 264 blue, 298 violet, 354 pink. Unlike hex codes, changing only the hue keeps the lightness the same, so text stays readable.

Example: make EduMate maroon. Change the hue 264 to 15 in the two --color-primary lines: light-dark(oklch(0.45 0.16 15), oklch(0.74 0.12 15)), and the same for --color-primary-hover. Every button, link, focus ring, soft background and gradient follows, in both themes.

Animation speed. CSS transitions use --duration* and --ease-*. The JavaScript animations take their curves and springs from motion/presets.ts (EASE_OUT, SPRING, fadeUp, pageVariants); change a number there and every page follows. The smoothness of the page scrolling is SMOOTH_SCROLL_LERP in config.ts (0.1: lower = floatier, 1 = no smoothing).

Switching animations off needs no code: every animation respects the computer's "reduce motion" setting (Windows: Settings → Accessibility → Visual effects → Animation effects; macOS: Accessibility → Display → Reduce motion).

Component styles (how cards, tables, the menu and the upload box look) are in app.css, the public welcome and login pages in landing.css; they use the tokens, so they rarely need editing.

Recipe 6: add a new page with a menu link

  1. Create frontend/src/pages/…/MyNewPage.tsx (copy a simple one such as MyLibraryPage.tsx). Start it with <PageHeader title={…} /> and use Loading, ErrorBanner, EmptyState and cards from components/ui.tsx, so it looks and behaves like every other page. Wrap lists in <Stagger> / <StaggerItem> for the one-after-another entrance.
  2. Add its texts to messages.ts.
  3. In App.tsx, load it lazily, so its code is only downloaded when someone opens it: const MyNewPage = lazyPage(() => import('./pages/student/MyNewPage'), 'MyNewPage'); and add <Route path="my-new" element={only(['STUDENT'], <MyNewPage />)} />.
  4. Add { to: '/my-new', label: t.nav.myNew, icon: Sparkles, section: s.studies } to the role's menu in navigation.ts (any icon from lucide.dev/icons). The same line automatically adds the page to the command palette, the breadcrumb, the eyebrow above its title and the dashboard's "Jump back in" list.
  5. If it needs new data: a controller method, its service, a line in RoleMatrix.java, a type in api/types.ts and an entry in api/endpoints.ts.
  6. Run npm test: navigation.test.ts checks that every menu item has an icon and that each section's links sit together.

Recipe 7: add a new document type

  1. Add a line to DocumentType.java, e.g. TRANSFER_CERTIFICATE("Transfer certificate", Set.of(FileKind.PDF), false),.
  2. Add it to DocumentType in api/types.ts, ACCEPTED_KINDS in fileChecks.ts, documentTypes in messages.ts, and DOCUMENT_ORDER in ApplyPage.tsx.
  3. No database change is needed: the type is stored as text.

Recipe 8: add a campus

Add an entry under edumate.tenants in application.yml (code, name, city) and restart: TenantProvisioner creates it. Then create its programmes and an administrator account for it.

Recipe 9: change the demo data or demo accounts

The demo data is made by DemoDataSeeder.java (names, marks, fees, books, applications). The password is DEMO_PASSWORD there and in config.ts. The list and descriptions of accounts on the login page are DEMO_USERNAMES in config.ts and login.demoAccounts in messages.ts. Several tests rely on specific demo records (Aarav's marks, Kiran's missing mark, Rohan's age), so change those only together with the tests.

Recipe 10: regenerate this guide after changing code

python docs/explainer/build_explainer.py --report

It re-reads every file, so the code shown here is always the current code. --report lists any lines that no longer have an explanation (for example after you add lines); hand-written explanations are in docs/explainer/notes/*.txt, and these chapters are in docs/explainer/chapters/*.html.
