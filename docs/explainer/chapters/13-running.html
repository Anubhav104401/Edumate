Running EduMate, and fixing common problems

What you need

  • JDK 21 or newer (the Java Development Kit). Check with java -version.
  • Node.js 20 or newer (includes npm). Check with node -v.
  • Git, to download the project: git clone https://github.com/Anubhav104401/Edumate.git.
  • Nothing else: Maven downloads itself (the wrapper), and the development database lives in memory.

Way 1: the helper script (Windows)

powershell -ExecutionPolicy Bypass -File scripts\dev-start.ps1

It opens two windows: the backend (port 8080) and the frontend (port 5173); the first time it also installs the frontend packages. When both say they are ready, open http://localhost:5173.

Way 2: by hand, in two terminals

Terminal 1:   cd backend
              ./mvnw spring-boot:run            (Windows: mvnw.cmd spring-boot:run)
              … wait for "Started EduMateApplication" and "Demo data ready"

Terminal 2:   cd frontend
              npm install                       (first time only)
              npm run dev
              … open http://localhost:5173

Opening http://localhost:5173 while signed out shows the public welcome page (/welcome): scroll down to see the scroll effects, then press Sign in. Log in with any demo account; the password for all is Edumate@2026. In development builds the login page lists every demo account as a searchable grid: click one to fill in the form, double-click to sign in straight away.

Once inside: Ctrl K (⌘K on a Mac) opens the command palette to jump to any page; the sun/moon button switches between light and dark; the arrow at the bottom of the sidebar collapses it to icons.

Way 3: Docker (production-like)

copy .env.example .env        (Linux/macOS: cp .env.example .env) — then edit the secrets
docker compose up --build
… open http://localhost:3000

This starts PostgreSQL 17, Redis 7, the backend and nginx. Data survives restarts (Docker volumes pgdata and uploads). docker compose down -v removes them.

  1. (signed out): the welcome page: the headline rising word by word, the product preview straightening as you scroll, the pinned "How it works" story, the sideways roles gallery.
  2. student: dashboard cards (numbers count up); My attendance (Operating Systems at exactly 75.00 %, still "On track"); Hall ticket (the stamp, Print); My results (the SGPA/CGPA chart: hover it, or Tab to it and use ← →); My fees → Pay now → choose "2 times (replay test)" → Approve payment → the check mark and confetti, PROCESSED + DUPLICATE_IGNORED; the statement shows one credit (TC-005/006).
  3. sneha.kulkarni: Marks entry → course SQA, exam session 2026-ODD → Kiran Joshi (23BTRCS015) has an empty internal mark → enter 31 with a reason → Save.
  4. examsup: Results workflow → Compute (60 results) → Approve; try Approve again → "A second, different exam superintendent must approve."
  5. examsup2: Approve → Publish → confirm. The Outbox fills with result e-mails.
  6. student: semester 5 appears with SGPA 8.63 (TC-013).
  7. student2: try http://localhost:5173/reports → "You do not have access to this page." Behind the screen, the backend refuses the report's API address itself with 403 and records ACCESS_DENIED in the audit log (TC-017, proved by SecurityIntegrationTest).
  8. applicant.minor: fill in, upload a photo and PDFs (try a renamed .exe → refused), Submit → refused; Send code to guardian → the demo code appears → Verify → Submit works (TC-020).
  9. admissions: Applications → open one → Start review → Shortlist; Merit list → M.Tech → Generate.
  10. admin: Timetable → Generate new draft → Move a lecture onto its teacher's other class → red clash → Publish draft refused (TC-011); Role matrix; Audit log.
  11. ccc.admin: sees only City Campus data (multi-tenancy).

Troubleshooting

SymptomCauseFix
"Cannot reach the EduMate server. Check that the backend is running on port 8080."the backend is not running, or is still startingstart it; wait for "Demo data ready"
Vite: "Port 5173 is already in use"another copy is running (strictPort refuses to switch)close the other window, or find it: netstat -ano | findstr :5173, then end that process
Backend: "Port 8080 was already in use"another program uses 8080stop it, or start with PORT=9090 and change the Vite proxy
"release version 21 not supported" / "UnsupportedClassVersionError"an older Javainstall JDK 21+; check java -version and JAVA_HOME
npm errors about syntax or enginesan old Node.jsinstall Node 20 or newer
"Too many failed attempts. Your account is locked until …"5 wrong passwordswait 15 minutes, or restart the backend (the dev database resets)
Logged out with "Your session has ended."the token expired (8 h) or was rejectedlog in again
Upload refused as "larger than 5 MB"the scan is too bigscan at a lower resolution (150–200 dpi is enough)
Upload refused as "does not look like a real PDF, JPEG or PNG file"the file's content is another format (for example HEIC photos from iPhones, or a Word file renamed)export or convert it to PDF/JPEG/PNG
My data disappeared after restartingdevelopment uses an in-memory databaseexpected; use Docker for data that persists
Docker: "Set JWT_SECRET in .env"no .env file, or a missing valuecopy .env.example to .env and fill it in
Docker: http://localhost:3000 shows nginx's 502the backend container is still starting (or crashed)docker compose logs backend
PowerShell: "running scripts is disabled"Windows execution policyuse -ExecutionPolicy Bypass as shown above
A page shows "This page could not be displayed."a bug while drawing that pageopen the browser console (F12) for the error; other pages still work
500 with "Please quote reference 3f2c9a1b"an unexpected server errorsearch the backend's console for traceId=3f2c9a1b to see the details

Building for production

cd backend  && ./mvnw package        → backend/target/edumate-backend-2.0.0.jar   (run: java -jar …)
cd frontend && npm run build          → frontend/dist/  (static files for any web server)

In production, set SPRING_PROFILES_ACTIVE=docker (or a similar profile) with a real PostgreSQL, a long random JWT_SECRET, a real PAYMENT_GATEWAY_SECRET, and DEMO_SEED=false, DEMO_EXPOSE_OTP=false. Serve everything over https.
