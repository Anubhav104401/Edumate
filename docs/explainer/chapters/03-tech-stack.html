The tech stack: every tool, why it was chosen, and what else could have been used

A tech stack is the list of languages, frameworks and tools a project is built with, stacked like layers: the browser at the top, the database at the bottom. The SQA report fixes the main layers ("a React single-page application, a Spring Boot REST backend, PostgreSQL, Redis, an object store"), and EduMate follows it exactly. The table gives every piece with its version.

Like building a house Languages are the raw materials (bricks, wood). Frameworks are ready-made parts (doors, windows): you could make your own, but using tested ones is faster and safer. Tools are the builder's equipment (the crane, the measuring tape).

Why each main piece, and what else could have been used

Java + Spring Boot for the backend

Chosen because: the report names a Spring Boot REST backend. Java is strongly typed (many mistakes are caught before running), has exact decimal arithmetic (BigDecimal, essential for money and GPAs), and Spring Boot gives security, transactions, validation and database access as tested parts, with no need to build them.

AlternativeWhat would change
Node.js (Express / NestJS)One language (TypeScript) on both sides. But JavaScript numbers are floating-point, so money and GPA need extra libraries, and transactions and locking need more hand-work.
Python (Django)Very fast to write, with a built-in admin site. Slower at run time, and dynamically typed, so more mistakes surface only when the code runs.
C# (ASP.NET Core)Technically very similar to Spring; would suit a Windows-centred university. Not what the report specifies.

React + TypeScript for the frontend

Chosen because: the report names a React single-page application. React describes each screen as a function of its data: when the data changes, React redraws only what changed. TypeScript checks that the frontend uses the backend's JSON correctly (for example that sgpa is a number) before the app even runs.

AlternativeWhat would change
AngularA complete framework with more built in (forms, HTTP client) but much more to learn and more code per screen.
Vue or SvelteSmaller and gentler to learn; equally able. Fewer people and libraries than React in Indian industry.
Server-rendered pages (Thymeleaf)No separate frontend at all; every click reloads a page. Simpler, but slower to use, and the report asks for an SPA.
Plain JavaScript instead of TypeScriptNo build-time type checks: a misspelt field name becomes an empty spot on screen instead of a build error.

PostgreSQL (and H2 for laptops)

Chosen because: the report names PostgreSQL. It is free, very reliable, and has strict transactions, row locks (SELECT … FOR UPDATE, used for payments), and UNIQUE and CHECK rules. EduMate relies on all of these for correctness. H2 in PostgreSQL mode lets anyone run EduMate on a laptop with nothing installed; the PostgresCompatibilityTest proves the same code also works on a real PostgreSQL.

AlternativeWhat would change
MySQL / MariaDBWould work with small SQL changes; historically looser with data by default.
MongoDB (document database)No joins or multi-row transactions in the same way; the cohort queries, the ledger and "exactly once" guarantees would be much harder.
PostgreSQL on laptops too (instead of H2)More realistic, but every developer must install and run a database first.

JWT tokens for login

Chosen because: the backend stays stateless: it remembers nothing between requests, so any number of backend copies can serve any request. The token proves who the user is with an HMAC-SHA256 signature. See chapter 7 for the alternatives (server sessions with cookies, OAuth with a university identity provider).

Vite

Chosen because: it starts in under a second and refreshes a component the moment its file is saved. Its proxy removes the need for CORS rules in development. Alternatives: webpack (slower, much more configuration); Create React App (no longer maintained).

Flyway

Chosen because: the database structure is written as numbered SQL files and applied in order, exactly once, on every database: laptop, test, production. Alternative: let Hibernate create tables automatically (ddl-auto: update). That is convenient, but it cannot express every rule (CHECK constraints, exact indexes), and it can silently alter a production database. EduMate sets ddl-auto: none.

Redis

Chosen because: the report lists Redis for cache data. On results morning thousands of students ask for the same published results; Redis answers from memory in well under a millisecond. On a laptop, a simple in-memory cache replaces it (spring.cache.type: simple).

nginx and Docker

nginx serves the built frontend files and forwards /api to the backend, adding security headers. Docker packs each program with everything it needs, so the same four containers (PostgreSQL, Redis, backend, frontend) run identically on any machine: docker compose up --build.

The Release 3.0 interface libraries

Release 3.0 redesigned every screen (see the chapter on the new look). Each library was chosen for one job it does better than hand-written code, and each is small, actively maintained and works with React 19.

LibraryWhy this oneAlternatives considered
motionDeclarative: an element says initial, animate and exit, and motion works out the rest. Springs, gestures, layout animations (an element sliding to its new place) and scroll-linked values, all respecting "reduce motion". Scroll-linked values change without redrawing React, so they stay at 60–120 frames a second.GSAP (very powerful timelines, but imperative code outside React's model); React Spring (physics only, no layout animations); CSS only (used where enough, e.g. hover effects, the marquee, scroll-reveal; but it cannot animate an element that is being removed).

Deliberately not used

  • No styled UI component library (Material UI, Bootstrap) and no Tailwind: hand-written CSS with design tokens keeps every colour, size and curve in one file (theme.css), keeps the markup readable line by line, and gives EduMate its own look. Radix supplies behaviour only.
  • No chart library (Recharts, Chart.js): the two charts (the attendance ring and the SGPA/CGPA trend) are about 200 lines of SVG in charts.tsx, fully animated, keyboard-accessible and themed, where a chart library would add 100–400 kB.
  • No state-management library (Redux): React's own state, context and the small useLoad hook are enough for these screens.
  • No HTTP library (Axios): the browser's built-in fetch, wrapped in one small file (http.ts).
  • No Lombok in Java: getters are written out, so every line can be read and explained.
