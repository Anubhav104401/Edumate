Computers from zero

Before any EduMate file makes sense, a few basic ideas are needed. Each one is small.

1. A program is a list of instructions

Like a recipe A recipe says: take two eggs, beat them, heat the pan, pour. A computer program says: take the marks, add them, compare with 40, print "Pass". The computer follows the steps exactly, very fast, and never gets bored.

Programs are written as text in a programming language (Java, TypeScript, SQL…). Another program (a compiler or interpreter) turns that text into something the machine can run.

2. Files, folders, bytes

Everything a computer stores is a file inside a folder. A file is a row of bytes. A byte is a number from 0 to 255. Text is stored by giving every letter a number (in UTF-8, A is 65, a is 97; ₹ takes three bytes). A photo is also just bytes, arranged in the PNG or JPEG way. This matters for uploads: EduMate looks at a file's first few bytes to find out what it really is (chapter 8).

Sizes: 1 KB = 1,024 bytes, 1 MB = 1,024 KB = 1,048,576 bytes. The upload limit, 5 MB, is 5,242,880 bytes.

3. Client and server

Like a restaurant You (the client) sit at a table and order from the menu. The kitchen (the server) cooks and sends back the dish. You never walk into the kitchen; you only talk to the waiter.

In EduMate, the browser (Chrome, Edge, Firefox) is the client. It shows the pages. The backend (a Java program) is the server. It keeps the data and applies the rules. They talk over the network using HTTP.

4. HTTP: how the two talk

HTTP is a very simple conversation: the client sends a request, the server sends back a response. Always in that order, one request, one response.

REQUEST                                     RESPONSE
GET /api/fees/me HTTP/1.1                   HTTP/1.1 200 OK
Host: localhost:5173                        Content-Type: application/json
Authorization: Bearer eyJhbGciOi…
                                            {"usn":"23BTRCS007","outstanding":62500.00, …}
  • The method says what kind of thing to do: GET read, POST create or act, PUT replace, DELETE remove.
  • The path (/api/fees/me) says what to do it to.
  • Headers are labels: who is asking (Authorization), what kind of body is attached (Content-Type), what kind of answer is wanted (Accept).
  • The body is the content (for EduMate: JSON, or the bytes of an uploaded file).
  • The response starts with a status code:
CodeMeaningExample in EduMate
200OKthe fee account was sent
204OK, nothing to send backa document was deleted

401who are you? (no valid login)no token, or an expired one

5. Addresses and ports

Like a block of flats The street address (host) gets you to the building; the flat number (port) gets you to the right door. One computer runs many programs, and each listens behind its own numbered door.

A web address such as http://localhost:8080/api/fees/me has four parts:

PartHereMeaning
schemehttpwhich language to speak (https = the encrypted version)
hostlocalhostwhich computer: localhost means "this same computer"
port8080which program on that computer
path/api/fees/mewhich thing inside that program

EduMate's programs and their ports are listed in chapter 4.

6. JSON: the shape of the data

The browser and the backend must agree on how to write data as text. EduMate uses JSON (JavaScript Object Notation):

{
  "usn": "23BTRCS007",            ← text goes in double quotes
  "outstanding": 62500.00,        ← numbers do not
  "minor": false,                 ← true / false
  "phone": null,                  ← "nothing"
  "courses": ["23CS501", "23CS502"],          ← a list, in square brackets
  "user": { "id": 12, "role": "STUDENT" }     ← an object inside an object
}

Every language can read and write JSON. In the browser, JSON.stringify(object) turns an object into this text and response.json() turns the text back. In Java, the library Jackson does the same for Java objects. Chapter 5 follows one JSON message all the way.

7. A database: the filing cabinet

Like a filing cabinet of ruled sheets Each drawer is a table (students, marks, payments). Each sheet is a row (one student). Each column on the sheet is a column (name, date of birth). Every sheet has a unique number, its id, so other sheets can point at it.

The database program (PostgreSQL in production, H2 on a laptop) keeps these tables on disk, makes sure two people cannot corrupt a row at the same time, and answers questions written in SQL:

SELECT full_name FROM student WHERE usn = '23BTRCS007';      → Aarav Sharma

8. Frontend and backend

  • Frontend: the part that runs in the browser and draws the screens (folder frontend/, written in TypeScript with React).
  • Backend: the part that runs on the server, holds the rules and talks to the database (folder backend/, written in Java with Spring Boot).

The golden rule of this design: the backend decides; the frontend only asks and shows. Anything the browser does can be changed by the person sitting at it, so every rule (who may do what, what counts as a valid file, whether results may be published) is checked on the server. The browser repeats some checks only to be quick and friendly.

9. Source code, building, running

Source code is the text people write. Building turns it into something runnable: Maven turns the Java code into one .jar file; Vite turns the TypeScript into plain JavaScript files a browser understands. Running starts it. Chapter 13 gives the exact commands.

10. Git and GitHub

Git keeps the full history of every file: who changed what, when, and why ("commits"). GitHub stores a copy online: this project lives at github.com/Anubhav104401/Edumate.
