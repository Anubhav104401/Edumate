Notes on the SQA report: discrepancies found, and known limitations

While turning the report into working code, a few numbers in the report turned out to be inconsistent. They are listed here so they can be corrected or explained at the viva. The code follows the correct values.

Known limitations of this implementation

  • Scale. The report describes a production system of about 48,600 lines. This repository is a working reference implementation of its core modules, so it is much smaller.
  • External systems. The university ERP and DigiLocker integrations named in the report are not implemented.
  • Simulated gateways. Payments go through MockPaymentGateway, which signs and delivers callbacks exactly as a real gateway would. E-mail and SMS are written to the log by LoggingNotificationGateway.
  • Not split by campus. The audit log and the message outbox are university-wide, so only university-level administrators should hold the ADMIN role.
  • Token revocation. A login token stays valid until it expires (8 hours); there is no server-side "log out everywhere".
  • Uploads. Files are checked by type and size, but not scanned for viruses, and images are not re-encoded.
  • Development database. H2 is in memory: data is recreated on every start. Use Docker (PostgreSQL) for data that must persist.
