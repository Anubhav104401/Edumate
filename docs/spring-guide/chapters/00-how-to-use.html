How to use this course

This is a course on Spring Boot, the most widely used framework for building server applications in Java. It assumes you can read and write ordinary Java (classes, interfaces, generics, lambdas, records, exceptions) and that you have never seen Spring at all. It ends at the level where you can explain what the framework does inside, extend it, and make architectural decisions with it.

The running example: EduMate

Most Spring tutorials build a to-do list. This course uses a real application instead: the EduMate backend in this repository (backend/). It runs admissions, attendance, examinations, fees, timetables and the library of a multi-campus university, with login tokens, role-based security, a database, caching, background jobs, file uploads and a test suite. Every Spring feature in this course is shown where EduMate really uses it.

Code blocks with a grey title bar are copied from the real files when this page is built, so they always match the code. The explained ↗ link on their title bar opens the same lines in the companion guide, EduMate: Zero to Hero, where every line is explained on its own.

What you need on your computer

  • A JDK, version 21 or newer (EduMate compiles for Java 21). Check with java -version.
  • An editor that understands Java: IntelliJ IDEA (Community edition is free) or VS Code with the Java and Spring Boot extensions. Both can run and debug a Spring Boot application with one click.
  • Nothing else. Maven is downloaded by the Maven Wrapper (mvnw) that is part of the project, and the development database (H2) runs inside the application.

Start the example application

cd backend
./mvnw spring-boot:run          # Windows: mvnw.cmd spring-boot:run

After some seconds of log lines you will see something like Tomcat started on port 8080 and Started EduMateApplication in 6.4 seconds. The backend is now answering on http://localhost:8080. Three quick checks from a second terminal:

# 1. Is it alive? (Spring Boot Actuator)
curl http://localhost:8080/actuator/health
#    {"status":"UP"}

# 2. Log in as the demo student and keep the token
curl -s -X POST http://localhost:8080/api/auth/login \
     -H "Content-Type: application/json" \
     -d '{"username":"student","password":"Edumate@2026"}'
#    {"token":"eyJhbGciOiJIUzI1NiJ9...","expiresAt":"...","user":{...}}

# 3. Call a protected address with the token
curl http://localhost:8080/api/attendance/me -H "Authorization: Bearer eyJhbGciOiJIUzI1NiJ9..."
#    [{"courseId":1,"courseCode":"23CS501","courseName":"Design and Analysis of Algorithms",
#      "held":32,"attended":30,"percent":93.75,"meetsThreshold":true,...}, ...]

# Without the token the answer is 401, and for an address the role may not use it is 403.

While it runs in development mode you can also open http://localhost:8080/h2-console (JDBC URL jdbc:h2:mem:edumate, user sa, empty password) to look at the tables Spring created. To see the whole product in a browser, start the frontend as well (cd frontend, npm install, npm run dev, then open http://localhost:5173).

Keep the code open next to this page Every chapter names the files it talks about. Open them in your editor, set a breakpoint, and watch Spring call your code. Seeing the call stack of a real request teaches more than any diagram.
