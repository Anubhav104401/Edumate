Troubleshooting: the errors everyone meets

Spring's error messages are long but precise. Find the last "Caused by:" in a stack trace, or the APPLICATION FAILED TO START box, and look it up here.

Start-up failures

Message (shortened)MeaningFix
Parameter 0 of constructor in X required a bean of type 'Y' that could not be found.nothing creates a YIs Y annotated (@Service…)? Is it under the main class's package? Is it conditional (profile, property) and switched off? Is the starter that provides it missing?
… required a single bean, but 2 were foundambiguous injection@Primary, @Qualifier, or create only one (profiles/conditions)
The dependencies of some of the beans in the application context form a cycleA needs B needs Aextract the shared part into a third bean, or use events; @Lazy only as a last resort
Failed to configure a DataSource: 'url' attribute is not specifiedJPA/JDBC is on the classpath but no database is configuredadd spring.datasource.url (or an embedded database like H2), or remove the starter
Web server failed to start. Port 8080 was already in use.another process (often an earlier run) holds the portstop it, or --server.port=8081
Validate failed: Migration checksum mismatch for migration version 1an applied Flyway file was editedundo the edit and write a new V2__…; on a throw-away development database, recreate it
Schema-validation: missing column [x] in table [y]an entity field without a column (with ddl-auto: validate)add a migration for the column
Failed to bind properties under 'edumate.security' … Failed to converta setting has the wrong typefix the value; the message names the property

A debugging routine that always works

  1. Read the whole message, then the last "Caused by:". Spring usually says exactly what is wrong.
  2. Turn up the logs for the suspected area: logging.level.org.springframework.web=DEBUG (request mapping), org.springframework.security=TRACE (the filter chain), org.hibernate.SQL=DEBUG (queries), org.springframework.transaction=TRACE (transaction boundaries).
  3. Ask the application about itself: --debug for the conditions report; Actuator's beans, mappings, configprops, env in development.
  4. Reproduce it in a test (MockMvc makes this quick), then fix it and keep the test.
  5. Set a breakpoint in the framework: DispatcherServlet.doDispatch, TransactionInterceptor.invoke, FilterChainProxy.doFilter. Stepping through Spring's code is how experts learn it.
