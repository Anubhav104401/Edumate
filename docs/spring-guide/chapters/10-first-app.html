Your first Spring Boot application

In this chapter you create a project, read its build file, meet the one class every Spring Boot application has, and follow step by step what happens between pressing Run and "Started".

Package by feature EduMate groups code by business module (attendance, fees, exam…), each holding its controller, services, entities and repositories. The other common style, package by layer (controllers/, services/, repositories/), spreads one feature over many folders. Package by feature keeps related code together and makes module boundaries visible, which matters when the application grows (see the Level 4 chapter on events and modules).

The build file, pom.xml

Maven reads pom.xml to know which libraries to download and how to build. Four parts matter.

1. The parent: tested versions for everything



Inheriting from spring-boot-starter-parent gives you a bill of materials (BOM): a list
of hundreds of libraries with versions that the Spring team has tested together. That is why the dependencies below
have no <version>: the parent decides. Upgrading Spring Boot means changing this one number.



2. Starters: one line per capability




A starter is an almost empty library whose only job is to depend on the right set of real
libraries. spring-boot-starter-webmvc brings Spring MVC, an embedded Tomcat server and Jackson for JSON;
spring-boot-starter-data-jpa brings Hibernate, Spring Data and a connection pool (HikariCP). In Spring Boot
4 the starters were split into smaller, more precise modules; that is why EduMate uses
spring-boot-starter-webmvc and spring-boot-starter-flyway where older projects used
spring-boot-starter-web and a plain Flyway dependency.



3. Scopes: when a library is needed






ScopeMeaningExample

4. The plugin: one runnable jar




spring-boot-maven-plugin adds mvnw spring-boot:run and repackages the build into a
fat jar: your classes and every library inside one file, with a small launcher that knows how
to load jars nested in a jar. The result, target/edumate-backend-2.0.0.jar, runs anywhere Java runs.



The starting point: @SpringBootApplication




That is the whole class. SpringApplication.run(...) starts Spring; the annotations tell it what to
switch on:




AnnotationMeaning



@SpringBootApplicationthree annotations in one: @SpringBootConfiguration (this class may declare beans), @EnableAutoConfiguration (let Boot configure what it finds on the classpath) and @ComponentScan (look for my classes in this package and every package below it)


@ConfigurationPropertiesScanfind classes annotated with @ConfigurationProperties (EduMate's AppProperties) and fill them from application.yml


@EnableCachingmake @Cacheable and @CacheEvict work


@EnableSchedulingmake @Scheduled methods run on their timers




Where the main class lives matters
Component scanning starts at the package of the main class (com.edumate) and goes down. A class in
com.edumate.fees is found; a class in com.other is silently ignored, and you get
"No qualifying bean" errors. Keep the main class in the top package.



What happens when you press Run


Here is the start-up of EduMate, in order. You can see most steps in the log.


    

  1. Prepare the environment. Read application.yml, then the file of the active profile
(application-dev.yml by default), environment variables and command-line arguments, into one set of
settings.
    2. 

  2. Create the application context, the container that will hold every object. Because Spring MVC is
on the classpath, it is a servlet web context.
    3. 

  3. Scan for your classes. Every class under com.edumate annotated with
@Component, @Service, @Repository, @RestController or
@Configuration becomes a bean definition: a recipe for an object. Interfaces extending
JpaRepository become repository recipes.
    4. 

  4. Add the auto-configurations whose conditions match: a DataSource because a JDBC driver
and a URL are present, an EntityManagerFactory because JPA is present, Flyway because it is on the
classpath, a JwtDecoder… unless EduMate already defined one (it did).
    5. 

  5. Create every singleton bean, each after the beans it needs. The DataSource opens its
pool; Flyway runs V1__create_schema.sql on the empty database; Hibernate checks the entity
classes; security builds its filter chain from the RoleMatrix.
    6. 

  6. Start Tomcat on port 8080 and register Spring MVC's DispatcherServlet.
    7. 

  7. Log "Started EduMateApplication in … seconds". The scheduler was switched on together with the
context: the outbox dispatcher runs 10 seconds after start, then every 5 seconds.
    8. 

  8. Run the start-up tasks: every ApplicationRunner, in order.
EduMate's TenantProvisioner creates the campuses, then DemoDataSeeder fills the demo data.
Only then is the application announced as ready (an ApplicationReadyEvent).
    9.

Your first endpoint


Add this class anywhere under com.edumate, for example
backend/src/main/java/com/edumate/admin/HelloController.java:


package com.edumate.admin;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class HelloController {

    @GetMapping("/api/hello")
    public Greeting hello() {
        return new Greeting("Hello from Spring Boot", java.time.Instant.now());
    }

    public record Greeting(String message, java.time.Instant at) {
    }
}


Restart and call curl -i http://localhost:8080/api/hello. You get… 403 Forbidden.
That is not a mistake: EduMate's security is deny by default. Every address must be listed in the
RoleMatrix. Add one line to its constructor (the "Any logged-in user" or "Public" group), for example
open(GET, "/api/hello");, restart, and you receive:


{"message":"Hello from Spring Boot","at":"2026-09-28T10:15:30.123Z"}


Notice what you did not write: no server code, no JSON code, no registration. Spring found the class
because of @RestController, mapped the method because of @GetMapping, and Jackson turned the
record into JSON. (Then delete the class again, or RoleMatrixCoverageTest will remind you it exists.)

Self-check


Why do the dependencies in EduMate's pom.xml have no version numbers?

The parent spring-boot-starter-parent provides a bill of materials with tested versions for them.
Only libraries outside that list (like embedded-postgres) need an explicit version.


What three annotations does @SpringBootApplication combine?

@SpringBootConfiguration, @EnableAutoConfiguration and @ComponentScan.


Why is the PostgreSQL driver in runtime scope?

EduMate's code never imports the driver's classes; it talks to the standard JDBC and JPA interfaces. The driver
is only needed when the program runs, so it is kept off the compile classpath.


Your new controller answers 403 although you are logged in. Why, in EduMate?

The RoleMatrix ends with anyRequest().denyAll(): an address that is not listed is
refused for everyone. Add a rule for it.
