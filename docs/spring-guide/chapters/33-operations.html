Running in production: Actuator, logging, observability and packaging

An application that works on your laptop is half the job. In production someone must know whether it is alive, why it is slow, what went wrong at 3 a.m., and how to ship a new version safely. Spring Boot's production features cover most of this with configuration, not code.

Actuator: the application's dashboard

Treat Actuator as an admin interface
/env can reveal secrets and /heapdump contains everything in memory. Expose only what you need,
protect the rest with security (EduMate's RoleMatrix opens only health and info), or serve
the management endpoints on a separate, internal port (management.server.port).
show-details: never hides which components are up or down from anonymous callers.



Health checks and orchestrators


Docker Compose, Kubernetes and load balancers ask "are you alive?" and "can you take traffic?". Spring Boot provides
liveness and readiness groups (/actuator/health/liveness,
/actuator/health/readiness), enabled automatically on Kubernetes. Readiness goes UP only after
the ApplicationRunners have finished, so no traffic reaches a half-started instance. You can write your own
indicator by implementing HealthIndicator (for example "the payment gateway is reachable").



Logging


Spring Boot logs through SLF4J (the API your code uses) with Logback underneath.
EduMate's classes use it like this:


private static final Logger log = LoggerFactory.getLogger(NotificationDispatcher.class);
…
log.warn("Sending notification {} failed: {}", message.getId(), ex.getMessage());


    

  • Levels: TRACE, DEBUG, INFO, WARN, ERROR. Set them per package in YAML
(logging.level.com.edumate: DEBUG in the dev profile) or at run time through /actuator/loggers.
    • 

  • Placeholders ({}) instead of string concatenation: the message is only built if the
level is enabled. Pass the exception as the last argument to get its stack trace
(log.error("…", traceId, ex) in GlobalExceptionHandler).
    • 

  • Never log secrets (passwords, tokens, OTPs, full card numbers) or more personal data than needed.
    • 

  • Structured logging: logging.structured.format.console=ecs (or logstash,
gelf) writes JSON lines that log platforms can search by field.
    • 

  • Correlation: EduMate's unexpected-error handler logs a short traceId and shows the same
id to the user, so a support request can be matched to its log line.
    • 




Observability: metrics and traces


Logs tell you what happened to one request; metrics tell you how the whole system behaves (requests
per second, 95th-percentile latency, pool usage, cache hit rate); traces follow one request across
services. Spring Boot instruments itself with Micrometer:


    

  • Add micrometer-registry-prometheus and expose prometheus: Prometheus scrapes
/actuator/prometheus, Grafana draws dashboards (http.server.requests per endpoint and status,
hikaricp.connections.active, cache.gets…).
    • 

  • Add tracing with OpenTelemetry (Spring Boot 4 has a starter for it) and every log line carries a trace id; a tracing
UI shows the time spent in each step of a request.
    • 

  • The Observation API (@Observed on a method, or Observation.createNotStarted(...))
produces a metric and a trace span from one piece of instrumentation, for your own important operations (computing
results, handling a payment callback).
    • 




Packaging and running


The fat jar


./mvnw package produces one runnable jar. Run it anywhere with a JRE:
java -jar edumate-backend-2.0.0.jar --spring.profiles.active=docker. Settings come from the environment (the
twelve-factor way), so the same artifact goes to test and to production.


Containers




    

  • Two stages: a JDK image builds; a much smaller JRE image runs. Compilers and sources never reach
production.
    • 

  • Dependencies first: copying pom.xml and downloading libraries before copying the code lets
Docker reuse that layer when only code changes.
    • 

  • Not root: the process runs as an unprivileged user that may only write its upload folder.
    • 

  • Alternatives: ./mvnw spring-boot:build-image builds an optimised image with Cloud Native
Buildpacks and no Dockerfile at all; Boot's layered jars split libraries and code into separate image layers.
    • 




Graceful shutdown


When a container is stopped, requests in progress should finish. Spring Boot enables graceful shutdown by default in
recent versions: on the stop signal Tomcat stops accepting new connections and waits for active requests
(spring.lifecycle.timeout-per-shutdown-phase, default 30 s), then beans are destroyed in order (pools closed,
schedulers stopped).

Self-check


Why does EduMate not expose /actuator/env?

It shows the effective configuration, which can include secrets; exposed publicly it would be an information leak.


What is the difference between liveness and readiness?

Liveness: is the process healthy or should it be restarted? Readiness: can it take traffic right now (started,
dependencies available)? An orchestrator restarts on failed liveness and stops routing on failed readiness.


Why use {} placeholders in log messages?

The message text is only assembled when the level is enabled, and values are formatted consistently; it also avoids
accidental expensive string building on hot paths.
