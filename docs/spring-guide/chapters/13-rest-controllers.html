Building a REST API with Spring MVC

A controller turns HTTP into method calls: an address and a verb choose the method, parts of the request become its parameters, and its return value becomes the response. This chapter covers every piece you need for a real JSON API, and follows a request through Spring MVC's machinery.

HTTP in two minutes

A request has a method (verb), a path, optional query parameters, headers and an optional body. A response has a status code, headers and a body.

PUT /api/attendance/sessions HTTP/1.1            ← method + path
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9…      ← headers
Content-Type: application/json

{"courseId":3,"section":"A","date":"2026-09-26","period":6,"version":0,"marks":[…]}   ← body

HTTP/1.1 200 OK                                   ← status
Content-Type: application/json

{"sessionId":41,"version":1,"courseCode":"23CS503",…}
MethodMeaning in a REST APIEduMate example
GETread, never changes anythingGET /api/attendance/me
POSTcreate something, or run an actionPOST /api/auth/login, POST /api/library/loans
PUTreplace / update a resourcePUT /api/attendance/sessions, PUT /api/exams/marks/{id}
DELETEremoveDELETE /api/admissions/documents/{id}

Status codes you will use constantly: 200 OK, 201 Created, 204 No Content, 400 bad input, 401 not logged in, 403 logged in but not allowed, 404 not found, 409 conflict with the current state (someone else saved first, already paid…), 413 too large, 500 a bug on the server.

Thin controllers
Look at how little each method does: read the request, check access, call a service, return the result. All rules
(future dates, stale versions, who belongs to a section) live in the service, where they can be tested without HTTP
and reused by other entry points. A controller method longer than a few lines is usually a sign that business logic
has leaked into the web layer.



Request and response bodies: records and JSON


Spring MVC uses Jackson (version 3 in Spring Boot 4) to convert between JSON text and Java objects.
Java records are ideal for this: their components become JSON fields, in order.




The request {"username":"student","password":"Edumate@2026"} becomes a LoginRequest; the
returned LoginResponse becomes:


{
  "token": "eyJhbGciOiJIUzI1NiJ9.eyJpc3MiOi…",
  "expiresAt": "2026-09-28T18:15:30.123Z",
  "user": { "id": 12, "username": "student", "fullName": "Aarav Sharma", "role": "STUDENT",
            "campusCode": "JGC", "studentId": 7 }
}


    

  • Instant, LocalDate and friends become ISO-8601 text ("2026-09-28"), which every
language can read.
    • 

  • Enums (Role.STUDENT) become their name, "STUDENT".
    • 

  • BigDecimal becomes an exact JSON number (62500.00), never a rounded double.
    • 

  • null fields are written as null (configurable).
    • 



Never return entities directly
It is tempting to return the JPA entity (AppUser) from a controller. Don't: you would leak fields (the
password hash!), tie your API to your table design, and risk "lazy loading" errors while JSON is written. EduMate always
returns small records made for the response (MeResponse, AttendanceSheet,
DocumentView). These are often called DTOs, data transfer objects.

File uploads




A multipart/form-data request carries fields and files. @RequestParam("type") reads a text
field (converted to the DocumentType enum), @RequestParam("file") MultipartFile the file:
its name, size, content type and bytes. The size limits in application.yml
(spring.servlet.multipart.*) are enforced by the server before this method is called.



What happens between Tomcat and your method


Tomcat thread receives PUT /api/attendance/sessions
  │
  ├─ Filters (Servlet filters, in order)
  │    └─ Spring Security's filter chain: Bearer token → verified JWT → authorities → RoleMatrix check
  │          (401 / 403 are sent from here; your controller is never reached)
  │
  └─ DispatcherServlet   ← Spring MVC's single entry point
       1. HandlerMapping: which @…Mapping matches "PUT /api/attendance/sessions"?  → AttendanceController.saveSheet
       2. HandlerAdapter prepares the call. For each parameter an argument resolver fills it:
             CurrentUser  ← CurrentUserArgumentResolver (EduMate's own)
             @RequestBody ← HttpMessageConverter (Jackson) reads the JSON; then @Valid runs Bean Validation
       3. Your method runs (and calls the service, inside a transaction)
       4. Return value handler: HttpMessageConverter (Jackson) writes the record as JSON
       5. If anything threw: @ExceptionHandler methods (GlobalExceptionHandler) build the error response


Every step is replaceable. That is how EduMate added its own parameter type.

Designing good REST addresses


    

  • Nouns for resources, verbs from HTTP: GET /api/library/loans, POST /api/library/loans.
Actions that are not simple CRUD become sub-resources: POST /api/library/loans/{id}/return,
POST /api/exams/result-sets/{id}/approve.
    • 

  • /me for "mine": /api/attendance/me, /api/fees/me. The server
decides who "me" is from the token.
    • 

  • Plural nouns, lower case, dashes: /result-sets, not /ResultSet.
    • 

  • Stable, documented errors: one JSON shape for every error (next chapter).
    • 

  • Versioning: when an API must change incompatibly, Spring Framework 7 has built-in API versioning
: you choose once how clients send the version (a header, a query parameter, the path or the media type) in
WebMvcConfigurer.configureApiVersioning, then map methods per version with
@GetMapping(path = "/…", version = "2"). EduMate, with one frontend it controls, does not need it yet.
    •

Self-check


What is the difference between @RequestParam and @PathVariable?

@PathVariable reads a named part of the path (/courses/{courseId});
@RequestParam reads a query parameter (?section=A) or a form field.


How does a record returned from a controller become JSON?

The return value handler of a @RestController hands it to an HttpMessageConverter; for
application/json that is Jackson, which writes each record component as a field.


Why does EduMate return MeResponse instead of the AppUser entity?

To expose only what the client may see (never the password hash), to keep the API independent of the table
design, and to avoid lazy-loading problems while writing JSON.


A logged-out request to /api/attendance/me gets 401. Does AttendanceController run?

No. Spring Security's filters run before the DispatcherServlet and send 401 themselves.
